# Лабораторная работа 3: Корпоративная система распределения сообщений

## Описание проекта

Данная лабораторная работа представляет собой корпоративную систему распределения сообщений с гибкой архитектурой доставки. Проект демонстрирует применение структурных паттернов проектирования в сочетании с принципами SOLID, GRASP и порождающими паттернами.

Система позволяет отправлять сообщения различным адресатам (пользователям, мессенджерам, дисплеям) с возможностью фильтрации по важности, логирования и группировки получателей.

## Цель работы

Отработать реализацию структурных паттернов проектирования и применить их совместно с ранее изученным материалом по ООП, SOLID и порождающим паттернам.

## Архитектура проекта

### Ключевые компоненты:

#### 1. Сообщения (MessageFiles)
- **`IMessage`** — интерфейс сообщения
- **`Message`** — реализация сообщения с заголовком, телом и уровнем важности

#### 2. Топики (TopicFiles)
- **`ITopic`** — интерфейс топика
- **`Topic`** — топик с названием и списком адресатов (Singleton)

#### 3. Адресаты (RecipientFiles)
- **`IRecipient`** — базовый интерфейс для всех адресатов
- **`RecipientGroup`** — группа адресатов (Composite pattern)

#### 4. Пользователи (UserFiles)
- **`User`** — пользователь системы с отслеживанием статуса сообщений
- **`RecipientUser`** — адаптер пользователя как адресата
- **`IRecipientUser`** — интерфейс пользователя-получателя

#### 5. Мессенджер (MessengerFiles)
- **`Messenger`** — вывод сообщений в консоль
- **`RecipientMessenger`** — адаптер мессенджера как адресата
- **`IRecipientMessenger`** — интерфейс для внешнего мессенджера

#### 6. Дисплей (DisplayFiles)
- **`Display`** — отображение сообщения с цветом
- **`RecipientDisplay`** — адаптер дисплея как адресата
- **`IDisplay`** — интерфейс дисплея

#### 7. Драйверы дисплея (DisplayDriverFiles)
- **`IDisplayDriver`** — интерфейс драйвера
- **`DisplayDriver`** — драйвер для вывода в консоль
- **`FileDisplayDriver`** — драйвер для вывода в файл

#### 8. Логирование (Logger)
- **`ILogger`** — интерфейс логгера
- **`ConsoleLogger`** — логирование в консоль
- **`FileLogger`** — логирование в файл
- **`RecipientLogging`** — декоратор для логирования сообщений

#### 9. Фильтрация (SignificanceFiles)
- **`SignificanceFilter`** — декоратор для фильтрации по важности
- **`SignificanceLevel`** — enum уровней важности (Low, Medium, High, ExtraHigh)

## Применённые паттерны

| Паттерн | Где используется | Назначение |
|---------|------------------|------------|
| **Singleton** | `Topic` | Единый экземпляр топика |
| **Decorator** | `SignificanceFilter`, `RecipientLogging` | Добавление функциональности фильтрации и логирования |
| **Composite** | `RecipientGroup` | Группировка адресатов |
| **Adapter** | `RecipientUser`, `RecipientMessenger`, `RecipientDisplay` | Адаптация различных типов получателей к единому интерфейсу `IRecipient` |
| **Strategy** | `IDisplayDriver`, `ILogger` | Различные стратегии вывода и логирования |

## Функциональность

### Сообщения
- Создание с заголовком, телом и уровнем важности
- Получение строкового представления

### Топики
- Управление адресатами (добавление/удаление)
- Рассылка сообщений всем адресатам

### Адресаты
- **Пользователь**: хранение сообщений с отслеживанием статуса (прочитано/не прочитано)
- **Мессенджер**: вывод в консоль с префиксом "Messenger:"
- **Дисплей**: вывод цветного текста с очисткой предыдущего сообщения
- **Группа**: массовая рассылка нескольким адресатам

### Фильтрация
- Настройка минимального уровня важности для адресата
- Сообщения ниже уровня не доставляются

### Логирование
- Логирование всех входящих сообщений
- Поддержка консольного и файлового вывода

## Тестирование

Проект покрыт модульными тестами (xUnit) с использованием библиотеки Moq для создания мок-объектов. Всего реализовано **16 тестов**, проверяющих различные аспекты системы:

### Тесты пользователя и статусов сообщений

| Тест | Описание | Проверка |
|------|----------|----------|
| `Test_Message_Status_Unread_To_Read` | При получении сообщения пользователем, оно сохраняется как "не прочитано". При отметке прочитанным статус меняется | Статус изменён на `true` |
| `Test_Message_Status_Already_Read` | Попытка отметить уже прочитанное сообщение | Возвращается `false` |
| `Test_ReceiveMessage_CallsUserReceiveMessage` | Проверка вызова метода получения сообщения у пользователя | Метод вызван 1 раз |

### Тесты фильтрации по важности

| Тест | Описание | Проверка |
|------|----------|----------|
| `Test_ReceiveMessage_High_Significance` | Сообщение с высоким уровнем важности проходит фильтр | Получатель вызван 1 раз |
| `Test_Message_Sending_To_Group_With_Filter` | Группа с фильтром: сообщения разной важности доставляются только подходящим адресатам | Вызовы соответствуют фильтрам |

### Тесты логирования

| Тест | Описание | Проверка |
|------|----------|----------|
| `Test_Message_Logging` | При получении сообщения вызывается логгер | Логгер вызван 1 раз |

### Тесты мессенджера

| Тест | Описание | Проверка |
|------|----------|----------|
| `Test_Message_Sending_To_Messenger` | Отправка сообщения в мессенджер | Метод записи вызван 1 раз |

### Тесты дисплея и драйверов

| Тест | Описание | Проверка |
|------|----------|----------|
| `Test_ReceiveMessage_CallsShowMessage` | Адресат-дисплей вызывает метод отображения | `ShowMessage` вызван 1 раз |
| `Test_WriteText_WritesToFile` | Запись текста в файл через драйвер | Текст содержится в файле |
| `Test_ClearDisplay_ClearsFile` | Очистка файла через драйвер | Файл пуст |

### Тесты топика

| Тест | Описание | Проверка |
|------|----------|----------|
| `Test_GetName_ReturnsCorrectName` | Установка и получение имени топика | Имя совпадает |
| `Test_SendMessage_SendsMessageToAllRecipients` | Отправка сообщения всем адресатам | Все получатели вызваны 1 раз |
| `Test_SendMessage_DoesNotSendMessageToRemovedRecipient` | Удалённый адресат не получает сообщения | Удалённый не вызван |
| `Test_AddRecipient_AddsRecipientToList` | Добавление адресата в топик | Адресат получает сообщение |
| `Test_RemoveRecipient_RemovesRecipientFromList` | Удаление адресата из топика | Адресат не получает сообщение |

### Тесты пользователя-адресата

| Тест | Описание | Проверка |
|------|----------|----------|
| `Test_MarkMessageStatus_CallsUserMarkMessageStatus` | Проверка вызова метода отметки статуса | Метод вызван 1 раз |

## Нефункциональные требования

- **Тестируемость**: все внешние зависимости замоканы с помощью Moq
- **Изоляция**: мессенджер и дисплей не зависят от логики доставки
- **SOLID**: каждый класс имеет единственную ответственность
- **Структурные паттерны**: Decorator, Composite, Adapter
- **Порождающие паттерны**: Singleton
- **Инкапсуляция**: поля классов — private, доступ через методы
- **Покрытие тестами**: 16 тестов, покрывающих все ключевые сценарии

## Запуск проекта

1. Клонируйте репозиторий
2. Откройте решение в среде разработки (Rider/VS 2022+)
3. Соберите проект
4. Установите NuGet пакеты (при необходимости):
   ```bash
   dotnet add package Moq
   dotnet add package xunit
   ```
5. Запустите тесты через Test Explorer или командой:
   ```bash
   dotnet test
   ```

## Принципы проектирования

- **Single Responsibility**: каждый класс отвечает за одну функцию
- **Open/Closed**: расширение через декораторы, без изменения кода
- **Liskov Substitution**: все адаптеры корректно реализуют интерфейсы
- **Interface Segregation**: интерфейсы минимальны и специфичны
- **Dependency Inversion**: зависимость от абстракций, а не конкретных классов

## Особенности реализации

- **Декораторы** для добавления сквозной функциональности
- **Адаптеры** для интеграции разнородных компонентов
- **Компоновщик** для групповой рассылки
- **Стратегия** для различных способов вывода и логирования
- **Mock-объекты** в тестах для изоляции компонентов
