# Лабораторная работа 1: Симулятор транспортного маршрута поездов на магнитной подушке

## Описание проекта

Данная лабораторная работа представляет собой симулятор автоматизированного транспортного маршрута для поездов на магнитной подушке. Проект демонстрирует применение основных принципов объектно-ориентированного программирования: инкапсуляции, наследования, полиморфизма и композиции.

Симулятор позволяет моделировать прохождение поездом различных участков маршрута, вычислять время в пути и проверять успешность прохождения маршрута с учётом физических ограничений поезда и требований участков.

## Цель работы

Освоить основные принципы ООП и применить на практике знания о работе с объектно-ориентированным кодом на C#.

## Архитектура проекта

Проект разделён на несколько логических модулей:

### 1. Поезда (TrainFiles)
- **`ITrain`** — интерфейс, определяющий контракт для всех поездов
- **`Train`** — реализация поезда с атрибутами:
  - Масса (weight)
  - Скорость (speed)
  - Ускорение (acceleration)
  - Максимально допустимая сила (maxForce)
- **`ErrorTimeException`** — кастомное исключение для ошибок вычисления времени

### 2. Участки маршрута (PathFiles)
- **`IPath`** — базовый интерфейс для всех участков маршрута
- **`ConventMagneticPath`** — обычный магнитный путь с фиксированной продолжительностью
- **`ForceMagneticPath`** — силовой магнитный путь, прикладывающий силу к поезду
- **`Station`** — станция с ограничением по скорости прибытия

### 3. Маршруты (RouteFiles)
- **`IRoute`** — интерфейс маршрута
- **`Route`** — реализация маршрута как композиции участков

## Функциональность

### Поезд (Train)
- Расчёт времени прохождения дистанции с заданной точностью (итеративный метод)
- Изменение ускорения при приложении силы (F = ma)
- Проверка допустимости приложенной силы
- Обработка граничных случаев (нулевая скорость/ускорение, отрицательная скорость)

### Участки маршрута
1. **Обычный магнитный путь** — проверяет возможность преодоления дистанции
2. **Силовой магнитный путь** — прикладывает силу к поезду и проверяет прохождение дистанции
3. **Станция** — проверяет, не превышает ли скорость поезда допустимый лимит

### Маршрут (Route)
- Последовательное прохождение участков
- Аккумуляция общего времени в пути
- Проверка успешности всего маршрута
- Остановка поезда в конце маршрута с проверкой допустимой скорости

## Тестирование

Проект покрыт модульными тестами (xUnit), реализующими все 8 сценариев из задания:

| Сценарий | Описание | Результат |
|----------|----------|-----------|
| 1 | Ускорение + обычный путь | Успех |
| 2 | Переускорение + обычный путь | Неудача |
| 3 | Ускорение + путь + станция + путь | Успех |
| 4 | Переускорение для станции + станция + путь | Неудача |
| 5 | Переускорение для маршрута + путь + станция + путь | Неудача |
| 6 | Сложный маршрут с ускорениями и замедлениями | Успех |
| 7 | Только обычный путь | Неудача |
| 8 | Ускорение + двойное замедление | Неудача |

## Нефункциональные требования

- Инкапсуляция: все поля классов — private
- Сокрытие: реализация скрыта за интерфейсами
- Иммутабельность: типы маршрутов и участников не изменяют своё состояние
- Отсутствие исключений для бизнес-логики (исключения только для технических ошибок)
