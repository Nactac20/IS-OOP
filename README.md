# Лабораторная работа 5: Система банкомата

## Описание проекта

Данная лабораторная работа представляет собой консольное приложение для симуляции работы банкомата с многослойной архитектурой. Проект демонстрирует применение принципов чистой архитектуры (гексагональная/луковая архитектура), паттернов проектирования и работы с персистентным хранением данных в PostgreSQL.

Система позволяет пользователям создавать счета, просматривать баланс, снимать и пополнять средства, а также просматривать историю операций. Администраторы имеют доступ к управлению счетами.

## Цель работы

Проверить освоение многослойных архитектур и принципов их построения при разработке приложения.

## Архитектура проекта

Проект реализован с использованием **гексагональной (луковой) архитектуры**, разделяющей приложение на независимые слои:

### Слои архитектуры:

#### 1. Доменные модели (Application.Models)
- **`Account`** — модель банковского счета (логин, пароль)
- **`User`** — модель пользователя (имя, роль, пароль)
- **`Transaction`** — модель транзакции (ID счета, сумма, тип операции)
- **`TransactionType`** — enum типов транзакций (Refill, Withdrawal)

#### 2. Контракты (Application.Contracts)
- **`IUserService`** — интерфейс сервиса пользователя
- **`IAdminService`** — интерфейс сервиса администратора
- **`ICurUserService`** — интерфейс текущего пользователя
- **`ICurAccountService`** — интерфейс текущего счета
- **`LogResult`** — иерархия результатов операций (Success/Failure)

#### 3. Абстракции (Application.Abstractions)
- **`IUserRepository`** — репозиторий пользователей
- **`IAccountRepository`** — репозиторий счетов
- **`ITransactionRepository`** — репозиторий транзакций

#### 4. Бизнес-логика (Application)
- **`UserService`** — реализация операций пользователя
- **`AdminService`** — реализация операций администратора
- **`CurAccountService`** — сервис текущего счета
- **`CurUserManager` / `CurAccountManager`** — менеджеры состояния

#### 5. Инфраструктура (Infrastructure.DataAccess)
- Реализации репозиториев с PostgreSQL
- Мапперы и контекст базы данных
- Миграции FluentMigrator

#### 6. Презентация (Presentation.Console)
- Консольный интерфейс с Spectre.Console
- Сценарии для пользователя и администратора
- Обработка ввода/вывода

#### 7. Точка входа (Program.cs)
- Конфигурация DI-контейнера
- Запуск приложения

## Применённые паттерны

| Паттерн | Где используется | Назначение |
|---------|------------------|------------|
| **Dependency Injection** | Весь проект | Инверсия управления и слабая связанность |
| **Repository** | Все *Repository интерфейсы | Абстракция доступа к данным |
| **Unit of Work** | Косвенно через транзакции | Группировка операций с БД |
| **Strategy** | Разные сценарии в презентации | Инкапсуляция алгоритмов |
| **Result Object** | `LogResult` | Явное представление результата операции |
| **Singleton** | Менеджеры состояния | Единая точка доступа к текущему состоянию |

## Функциональность

### Режим пользователя

| Операция | Описание |
|----------|----------|
| **Вход в систему** | Аутентификация по логину и паролю |
| **Создание счета** | Регистрация нового счета |
| **Просмотр баланса** | Отображение текущего баланса |
| **Снятие средств** | Списание денег со счета (с проверкой остатка) |
| **Пополнение счета** | Зачисление денег на счет |
| **История операций** | Просмотр всех транзакций по счету |

### Режим администратора

| Операция | Описание |
|----------|----------|
| **Вход в систему** | Аутентификация по системному паролю |
| **Просмотр всех счетов** | Список всех зарегистрированных счетов |
| **Удаление счета** | Удаление счета пользователя |

## Тестирование

Проект покрыт модульными тестами с использованием библиотеки NSubstitute для создания мок-объектов:

| Тест | Описание | Проверка |
|------|----------|----------|
| `GetBalance_WithValidAccount_ReturnsSuccess` | Получение баланса существующего счета | Success |
| `GetBalance_WithNoAccount_ReturnsFailure` | Получение баланса без выбранного счета | Failure |
| `WithdrawMoney_WithSufficientBalance_ReturnsSuccess` | Снятие при достаточном балансе | Success, транзакция сохранена |
| `WithdrawMoney_WithInsufficientBalance_ReturnsFailure` | Снятие при недостаточном балансе | Failure, транзакция не сохранена |
| `Login_WithValidCredentials_ReturnsSuccess` | Вход с корректными данными | Success |
| `Login_WithInvalidCredentials_ReturnsFailure` | Вход с некорректными данными | Failure |
| `CreateAccount_WithExistingUsername_ReturnsFailure` | Создание счета с существующим именем | Failure |
| `DeleteAccount_WithAdminRole_ReturnsSuccess` | Удаление счета администратором | Success |
| `DeleteAccount_WithNonAdminRole_ReturnsFailure` | Удаление счета не-администратором | Failure |

## Запуск проекта

### Предварительные требования

- .NET 8.0 SDK
- PostgreSQL (локально или в контейнере)

### Настройка базы данных

1. Убедитесь, что PostgreSQL запущен
2. Настройте строку подключения в `Program.cs`:
   ```csharp
   configuration.Host = "localhost";
   configuration.Port = 6432;
   configuration.Username = "postgres";
   configuration.Password = "postgres";
   configuration.Database = "postgres";
   ```

### Запуск приложения

```bash
dotnet run --project Lab5
```

### Запуск тестов

```bash
dotnet test
```

## Используемые технологии

- .NET 8.0

- **FluentMigrator** для миграций
- **Spectre.Console** для красивого консольного интерфейса

- **Microsoft.Extensions.DependencyInjection** для DI

## Принципы проектирования

- **Single Responsibility**: каждый слой отвечает за свою область
- **Dependency Inversion**: зависимости направлены на абстракции
- **Interface Segregation**: интерфейсы минимальны и специфичны
- **Open/Closed**: расширение через новые сценарии без изменения существующих

## Особенности реализации

- **Чистая архитектура**: бизнес-логика не зависит от внешних слоев
- **Результат-объекты**: явное представление успеха/неудачи операций
- **Моки в тестах**: изоляция бизнес-логики от инфраструктуры
- **Красивый UI**: цветной вывод, таблицы, меню через Spectre.Console
- **Миграции**: автоматическое создание и обновление схемы БД
