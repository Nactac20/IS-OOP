# Лабораторная работа 2: Конструктор образовательных программ

## Описание проекта

Данная лабораторная работа представляет собой систему для формирования и редактирования образовательных программ в абстрактном университете. Проект демонстрирует применение основных принципов ООП, SOLID, GRASP и порождающих паттернов проектирования.

Система позволяет создавать и управлять пользователями, лабораторными работами, лекционными материалами, предметами и образовательными программами с соблюдением прав доступа и бизнес-правил.

## Цель работы

Отработать реализацию порождающих паттернов проектирования и применить их совместно с ранее изученным материалом по ООП и SOLID.

## Архитектура проекта

Проект разделён на несколько логических модулей:

### 1. Пользователи (UserFiles)
- **`User`** — пользователь системы с идентификатором и именем
- **`RepositoryUser`** — in-memory репозиторий для хранения пользователей (Singleton)

### 2. Учебные материалы (MaterialsFiles)
- **`Laboratory`** — лабораторная работа с атрибутами:
  - Идентификатор, наименование, описание, критерии оценивания, баллы
  - Автор и возможность клонирования (Prototype pattern)
  - Проверка прав при изменении
- **`Lectures`** — лекционные материалы с контентом
  - Поддержка клонирования и проверки автора
- **`RepositoryLaboratory`** и **`RepositoryLectures`** — репозитории для хранения материалов (Singleton)

### 3. Предметы (SubjectFiles)
- **`Subject`** — предмет с лабораторными и лекционными материалами
- **`ISubjectBuilder`** — интерфейс строителя для предметов (Builder pattern)
- **`SubjectExamBuild`** — реализация строителя для экзаменационного формата
- **`RepositorySubject`** — репозиторий предметов (Singleton)

### 4. Образовательные программы (ProgramFiles)
- **`Program`** — образовательная программа с предметами по семестрам
- **`RepositoryProgram`** — репозиторий программ (Singleton)

## 🎨 Применённые паттерны

| Паттерн | Где используется | Назначение |
|---------|------------------|------------|
| **Singleton** | Все репозитории | Гарантирует единственный экземпляр хранилища |
| **Prototype** | Laboratory.CloneLab(), Lectures.CloneLec() | Создание копий существующих сущностей |
| **Builder** | SubjectExamBuild | Пошаговое создание сложного объекта Subject |
| **Repository** | Все *Repository классы | Абстракция хранения и поиска сущностей |

## Функциональность

### Пользователи
- Создание пользователя с уникальным ID
- Поиск пользователя по имени или ID

### Лабораторные работы
- Создание с указанием названия, описания, критериев и баллов
- Клонирование существующей работы (с сохранением ID родителя)
- Изменение только автором (баллы неизменны)

### Лекционные материалы
- Создание с контентом
- Клонирование с сохранением родительского ID
- Изменение только автором

### Предметы
- Поддержка двух форматов: экзамен и зачёт
- Для экзамена — количество баллов
- Для зачёта — минимальный проходной балл
- Сумма баллов всегда равна 100
- Клонирование с сохранением родительского ID
- Неизменяемый список лабораторных работ при редактировании

### Образовательные программы
- Привязка предметов к семестрам
- Назначение ответственного лица и руководителя

## Тестирование

Проект покрыт модульными тестами (xUnit), проверяющими ключевую функциональность:

| Тест | Описание | Ожидаемый результат |
|------|----------|---------------------|
| `UpDateLab_NonAuthor_False` | Не автор пытается изменить лабораторную | False |
| `CloneLab_ContainsParentId` | Клон лабораторной содержит ID оригинала | Проверка parent ID |
| `UpDateLec_NonAuthor_False` | Не автор пытается изменить лекцию | False |
| `CloneLec_ContainsParentId` | Клон лекции содержит ID оригинала | Проверка parent ID |
| `CheckBuild_InvalidPoints_False` | Предмет с суммой баллов ≠ 100 | False |
| `CheckBuild_ValidPoints_True` | Предмет с суммой баллов = 100 | True |
| `CreateUser_ReturnsUserWithCorrectId` | Создание пользователя | ID не null |

## Нефункциональные требования

- **SOLID**: каждый класс имеет единственную ответственность
- **Инкапсуляция**: поля классов — private, доступ через методы
- **Полиморфизм**: интерфейсы для строителей
- **Порождающие паттерны**: Prototype, Builder, Singleton
- **Репозитории**: in-memory реализация с Dictionary
- **Иммутабельность** критических данных

## Используемые технологии

- .NET 8.0
- C# 12
- xUnit для модульного тестирования
- LINQ для работы с коллекциями

## Принципы проектирования

- **Single Responsibility**: каждый класс отвечает за одну сущность
- **Open/Closed**: классы открыты для расширения через наследование/интерфейсы
- **Liskov Substitution**: корректное наследование
- **Interface Segregation**: интерфейсы не перегружены методами
- **Dependency Inversion**: зависимость от абстракций

## Особенности реализации

- Генерация уникальных ID через статические счётчики
- Lazy-инициализация Singleton репозиториев
- Проверка прав доступа при модификации
- Сохранение связей между сущностями через ID
- Валидация бизнес-правил (сумма баллов = 100)
